## Challenge — with mechanical evidence

| # | Item | Status | The argument |
|---|---|---|---|
| 12 | `declare_check` is "just writing a file" | challenge | **No.** `evaluate.ts:419` — the handler calls `await baseline(mirrorNode, …)`, so the harness reads the mirror node **at the instant of declaration**, before the agent acts. "The balance rose by 2.5" is unverifiable unless something recorded the balance beforehand; an agent writing JSON at the end has lost that moment permanently. The tool is not recording a claim, it is triggering a measurement at a specific time — exactly the case Jake himself allows. |
| 13 | `submit_verdict` is "just writing a file" | partly concede | Weaker, and most of it concedes. The part that does not: `_meta: {"claude/endTurn": true}`. Answering ends the turn. A file write cannot do that, and the one time the evaluator decided for itself when it was done, it ended without answering at all. |
| 14 | "The agent can just curl the mirror node" | challenge | Inverts the premise. The harness does not read the chain because the agent *cannot* — it reads because an agent that curls and reports the result is an agent reporting its own success, which the README's first line says this project will not do. The override rule only means anything because the harness did the reading. **Be straight about the evidence:** settled checks have failed 3 times across 2 runs, all on real transactional specs — but the judge had already failed the run each time, so the override has never yet been *decisive*. Exercised, not yet proven. |
